# گزارش فارسی ترنسکریپت هکاتون Wallex / Starcoach

> **وضعیت سند:** این صفحه، ادعاهای متن ترنسکریپت ارسالی کاربر را از الزامات پروژه جدا می‌کند. متن فارسی در [فایل منبع](../research/user-sources/wallex_hackathon_audio_transcript_fa.md) عیناً از پیام ارسالی حفظ شده است؛ خود پیام، آن را «ترنسکریپت کاری پاک‌سازی‌شده و بازسازی‌شده از متن پرخطا» معرفی می‌کند. **فایل صوتی یا متن خام ASR در دسترس نیست و متن با شنیدن صدا مستقلاً راستی‌آزمایی نشده است.** بنابراین این متن نه نقل‌قول تأییدشده از صداست و نه سند رسمی مسابقه.

## شناسنامه و کیفیت منبع

- شناسه منبع: `USER-WALLEX-HACKATHON-AUDIO-TRANSCRIPT`؛ ثبت در [دفتر منابع](../research/source-register.yaml).
- نوع: متن گفتاربه‌نوشتار فارسی که داخل پیام کاربر آمده؛ نه فایل صوتی و نه متن خام شناخته‌شده.
- گوینده در متن خود را «سارا بهبودی» معرفی می‌کند؛ نسبت او به تیم Starcoach و املای نام در این گزارش فقط **به نقل از ترنسکریپت** است، نه هویت‌سنجی مستقل.
- بازه زمانی در مشخصات پیام «حدود ۰۰:۰۰:۰۰ تا ۰۰:۰۳:۵۴» ذکر شده؛ آخرین قطعه قابل مشاهده زمان `00:03:33` دارد. درباره ۲۱ ثانیه پایانی چیزی استنباط نمی‌شود.
- عبارت‌های آغازین و واژه «پردکتور» در `00:00:00` و `00:00:05` مبهم/احتمالاً خطادارند؛ در فایل منبع اصلاح نشده‌اند و در این گزارش معنای تازه‌ای به آن‌ها نسبت داده نمی‌شود.
- SHA-256 فایل متنی حفظ‌شده در source register آمده است. این hash فقط متن در دسترس را شناسایی می‌کند، نه فایل صوتی، متن خام ASR یا اصالت گفته‌ها.

## خلاصه‌ی نیازمندی‌ها بر مبنای ترنسکریپت

موارد این بخش «گزارش متن ترنسکریپت» هستند؛ برای وضعیت تطبیق با منابع دیگر به جدول بعد مراجعه کنید.

1. **هدف عامل (`00:00:09`)**: دریافت داده بازار، بررسی و تحلیل، تولید پیشنهاد خرید/فروش و انجام خودکار معاملات طبق الگوریتم و استراتژی مشخص. این توصیف به‌تنهایی مجوز ساخت یا فعال‌کردن اجرای زنده نیست.
2. **اولویت فنی (`00:00:29`, `00:03:33`)**: موتور، الگوریتم و استراتژی مهم‌تر از رابط کاربری‌اند؛ بازتولیدپذیری و امکان بررسی فنی نیز مهم دانسته شده‌اند.
3. **ابزارها (`00:00:51`, `00:01:05`)**: متن از انعطاف در استفاده از ابزارهای AI، تحلیل داده، coding agents و agentic AI می‌گوید و Wallex API و Wallex MCP را نام می‌برد. این ادعاها درباره امکان/مجوز مسابقه یا قابلیت دقیق ابزارها از روی ترنسکریپت تأیید رسمی نمی‌شوند.
4. **آزمون (`00:01:28`, `00:01:49`)**: بک‌تست تاریخی و shadow testing بدون تبدیل پیشنهادها به سفارش واقعی پیشنهاد شده‌اند. اشاره به ورود بعدی به بازار واقعی، مجوز عملیاتی نیست؛ این مخزن همچنان آفلاین است و اتصال live feed یا ارسال سفارش ندارد.
5. **سرمایه/تسویه (`00:02:09`)**: متن وجود سرمایه اولیه، منع برداشت در طول مسابقه و سازوکار کلی بازپس‌گیری اصل سرمایه/توزیع سود را توصیف می‌کند، اما مبلغ اولیه را در همین گفتار مشخص نمی‌کند.
6. **جوایز (`00:02:42`)**: متن می‌گوید جایزه Wallex برای برنده ۸۰ میلیون تومان است و جدا از جایزه تیم‌های برتر هکاتون؛ مبلغ دومی را خودش نامطمئن می‌داند. هیچ‌کدام در این ترنسکریپت به‌عنوان رقم رسمی تأییدشده ثبت نمی‌شود.
7. **دمو (`00:02:53`)**: متن می‌گوید ویدئو و توضیح پروژه ارسال شود و می‌گوید نبود ویدئو مانع داوری است. مهلت، قالب، محل ارسال و اثر دقیق عدم ارسال از متن حاضر معلوم نیست.
8. **قواعد بازار (`00:03:10`)**: متن از مجازبودن بعضی بازارها، ممنوعیت برخی دیگر و ممنوعیت Wash Trading می‌گوید؛ فهرست دقیق و نسخه جاری را تعیین نمی‌کند.

### وضعیت سه‌گانه بازار برای پروژه

این سه status، قرارداد fail-closed پروژه‌اند؛ نه ادعای فیلد رسمی API و نه مجوز account:

- **`ELIGIBLE`** — فقط وقتی همه شواهد مثبت، تازه، non-contradictory و معتبر باشند: Spot، active/orderable، challenge-permitted، خارج از disabled registry تأییدشده، quote/settlement مجاز، استراتژی و ریسک صریحاً موافق و precision/minimum semantics تأییدشده.
- **`INACTIVE`** — وضعیت صریح inactive/non-orderable، یا ممنوعیت صریح challenge در منبع معتبر؛ رد.
- **`UNKNOWN`** — داده غایب، stale، آینده‌دار، متناقض، synthetic خارج از test، غیرقابل‌اعتماد، یا مجوز challenge نامعلوم؛ رد.

این statusها را نباید با generic historical dataset validation یکی گرفت: وجود کندل تاریخی به هیچ‌وجه eligibility امروز/زمان challenge را ثابت نمی‌کند. Feature 002 replay فعلی generic/offline است و adapter بازار ندارد؛ هر strategy یا ارزیابی challenge-specific در آینده باید پیش از شمارش یک candidate trade، همین gate و evidence snapshot را اعمال کند. تمام candidate decisionها، حتی `HOLD` و vetoها، باید در run log و با version/config/data provenance ثبت شوند.

## الزامات اجرایی داخلی (تفسیر پروژه، نه قانون رسمی جدید)

- **`INFERRED`** — برای هر strategy آینده، ruleهای صریح ورود/خروج، رفتار deterministic، زمان‌بندی بدون look-ahead، هزینه‌های شفاف (fee/spread/slippage)، حسابداری portfolio و P&L تحقق‌یافته/نیافته، drawdown و exposure cap مستند شود.
- **`INFERRED`** — هر decision/trade باید به source data، feature snapshot، code commit، config hash، strategy/model version (اگر واقعاً وجود دارد)، risk verdict و simulated order/fill/rejection متصل باشد.
- **`INFERRED`** — out-of-sample checks و sensitivity analysis در صورت امکان برای جلوگیری از اتکا به یک دوره/تنظیم خاص ثبت شوند؛ نتیجه تاریخی/مصنوعی تضمین سود نیست.
- Backtesting، shadow، paper و live چهار حالت متفاوت‌اند. در این repo shadow/dry-run فقط محلی و بدون submitter هستند؛ live execution پیاده‌سازی نشده و برای این تغییر ممنوع است.

## موارد باز برای مالک/برگزارکننده

1. آیا Wallex MCP واقعاً جزء رسمی challenge است؟ URL رسمی، ابزارها، permission، محدودیت و نسخه آن چیست؟ تا پاسخ، پیکربندی یا ادعای قابلیت نمی‌شود.
2. آیا جایزه Wallex واقعاً ۸۰ میلیون تومان است؟ جایزه جداگانه تیم‌های برتر، شرایط و eligibility آن چیست؟ اطلاعیه رسمی و تاریخ لازم است.
3. deadline، محل، طول/فرمت و روش ارسال demo video چیست و اثر دقیق عدم ارسال کدام است؟
4. رقم و دسترسی سرمایه، زمان رسمی شروع/cutoff، فهرست فعال/مجاز، هزینه‌ها، تسویه و rubric نهایی را کدام سند رسمی نسخه‌دار تعیین می‌کند؟
5. آیا audio و raw ASR transcript در دسترس است تا واژه‌های خراب، نام/سمت گوینده و بازه پایانی بررسی شود؟ اکنون هیچ‌کدام موجود نیست.

**منبع رسمی قابل بررسی برای API docs در این مخزن:** [`MOD-INTRO`](https://developers.wallex.ir/docs)، [`MARKETS`](https://developers.wallex.ir/docs/basic-services-markets)، [`SPOT-MARKETS`](https://developers.wallex.ir/docs/spot-active-markets)، [`MOD-GENERATED-POST-ACCOUNT-ORDERS`](https://developers.wallex.ir/docs/generated/post-account-orders). این ارجاعات فقط مستندات صفحه را اثبات می‌کنند؛ نه runtime، permission مسابقه، availability حساب، MCP، یا اجرای زنده.
