# حساب و کلیدهای API

## ایجاد و دسترسی

صفحه جدید ساخت API-Key می‌گوید ابتدا اکانت موردنظر را انتخاب کنید؛ اکانت اصلی و هر اکانت اعتبار معاملاتی کلید جداگانه دارند. دسترسی‌ها شامل خواندن (پیش‌فرض)، معامله و برداشت است. برای برداشت، IP درخواست باید با IP ثبت‌شده مطابقت داشته باشد. کلید پس از تأیید یک‌بار نمایش داده می‌شود و حداکثر سه API-Key قابل ساخت است. نکته‌ها را از منبع جاری بازبینی کنید، چون این سیاست‌ها ممکن است تغییر کنند. [CREATE-KEY](https://developers.wallex.ir/docs/create-api-key)

صفحه مقدمه قدیمی می‌گوید مدت اعتبار کلید حداکثر ۹۰ روز قابل انتخاب است و پس از انقضا باید کلید جدید ساخت؛ فهرست IP خالی را دسترسی از همه IPها می‌داند. این ادعاها با سند جدید باید در تاریخ‌های بعدی دوباره مقایسه شوند؛ سند جدید صفحه دیده‌شده در این snapshot عدد ۹۰ روز یا همان IP rule را تأیید نمی‌کند. [LEGACY-API](https://api-docs.wallex.ir/)

## Authentication

مستند جدید API intro تشریح کامل header یا signing را در صفحه مقدمه ارائه نمی‌کند. مرجع قدیمی `X-API-Key: <api-key>` را برای endpointهای محافظت‌شده مثال می‌زند. صفحه‌های جدید endpoint لازم است پیش از هر طراحی، دقیق بررسی شوند؛ این مخزن هیچ کلیدی نساخته یا آزمایش نکرده است. [MOD-INTRO](https://developers.wallex.ir/docs) · [LEGACY-API](https://api-docs.wallex.ir/)

## حفاظت

کلید واقعی را در `.env`, issue, log یا source control قرار ندهید. فایل `.env.example` فقط placeholder خالی دارد. مجوز حداقلی را ترجیح دهید؛ مجوز برداشت یا استفاده از کلید اکانت اعتباری خارج از scope فعلی است.
