# Order book, trades, candles, history

## REST excerpts

- The basic-service prose page documents `GET /v1/depth` returning `result.ask` / `result.bid` levels with `price`, `quantity`, and `sum`; a generated page gives `GET https://api.wallex.com/v1/depth?symbol=...`. The all-markets depth generated page instead states `GET //api.wallex.com/depth/all` without `/v2`; the legacy guide lists `/v2/depth/all`. Hosts and paths remain distinct evidence. [DEPTH](https://developers.wallex.ir/docs/basic-services-depth) · [MOD-GENERATED-GET-MARKET-DEPTH](https://developers.wallex.ir/docs/generated/get-market-depth) · [MOD-GENERATED-GET-DEPTH](https://developers.wallex.ir/docs/generated/get-depth) · [LEGACY-API](https://api-docs.wallex.ir/) · [D-013](../research/discrepancies.md)
- Generated recent trades page states `GET https://api.wallex.com/v1/trades?symbol=...`, with `quantity`, `price`, `sum`, `isBuyOrder`, and a date-time `timestamp`; it labels `x-api-key` authorization. The legacy reference also lists `/v1/trades` but is not merged with this generated response contract. [MOD-GENERATED-GET-LATEST-TRADES](https://developers.wallex.ir/docs/generated/get-latest-trades) · [LEGACY-API](https://api-docs.wallex.ir/)
- The basic UDF page lists `symbol`, `resolution`, `from`, `to`; its displayed parameter table marks them Optional and lists `1, 15, 60, 240, 480, 720, 1D, 2D, 3D`. The generated UDF endpoint instead states `GET https://api.wallex.com/v1/udf/history` and marks all four query fields Required, with examples such as `1, 5, 15, 60, D`; the legacy guide also marks them Required. Response arrays include `t`, `c`, `o`, `h`, `l`, `v`. These sources disagree on requiredness and show `.ir` vs `.com` hosts; actual server validation is unknown. [CANDLES](https://developers.wallex.ir/docs/basic-services-candles) · [MOD-GENERATED-CANDLE-HISTORY](https://developers.wallex.ir/docs/generated/candle-history) · [LEGACY-API](https://api-docs.wallex.ir/) · [D-008](../research/discrepancies.md) · [D-015](../research/discrepancies.md)

## WebSocket candle updates

The new candle guide documents only `1m`, `1h`, and `1d` channel examples (`candle:<SYMBOL>@...`), UDF-shaped OHLCV strings, replacing an existing open candle by its `t` timestamp, and limited recovery via at most 10 recent messages kept for up to two minutes. The UDF history page presents additional resolution options. Do not assume every history resolution has a corresponding WebSocket channel. [MOD-SOCKET-CANDLE](https://developers.wallex.ir/docs/socket-candle) · [CANDLES](https://developers.wallex.ir/docs/basic-services-candles) · [D-014](../research/discrepancies.md)

The v2 trade feed sends new public trades and does not replay messages missed during disconnect. Buy/sell depth feeds publish complete snapshots (not deltas), but no initial snapshot is sent on subscription; reconnect does not recover missed snapshots. These are feed reliability constraints, not a runtime validation of either feed. [MOD-SOCKET-TRADE](https://developers.wallex.ir/docs/socket-trade) · [MOD-SOCKET-BUY-DEPTH](https://developers.wallex.ir/docs/socket-buy-depth) · [MOD-SOCKET-SELL-DEPTH](https://developers.wallex.ir/docs/socket-sell-depth) · [MOD-SOCKET-RAW-PROTOCOL](https://developers.wallex.ir/docs/socket-raw-protocol)

Rate limits, pagination, REST timestamp boundaries, maximum history windows, candle boundary alignment, market precision, and endpoint-specific auth remain unresolved or only partially documented. No request or WebSocket connection was made.
