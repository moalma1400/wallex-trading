# Wallex source research procedure

1. Read `.specify/memory/constitution.md`, `AGENTS.md`, Feature 001, and `docs/research/README.md` before research. Inspect the current register and unresolved questions so existing work is not duplicated or overwritten.
2. Start from official navigation/sitemaps or exact official links. Prefer Wallex-owned domains for exchange claims. Treat government sources as a separate evidence class and third-party sources as non-authoritative context.
3. Retrieve the page body through documented public, unauthenticated access only. Never log in, use API keys/cookies, probe production API routes, bypass geo/access controls, or call endpoints merely to test a claim.
4. Record the exact URL, retrieved UTC snapshot/time limitations, exact publisher date only if displayed, title, status, evidence, topic, and source relationships. `not_started` means no body review; partial tool/page output remains `in_progress`; do not mark a source validated because a validator passes.
5. Separate direct official statements, observations of returned content, inference, third-party claims, legacy claims, and unknowns. Preserve raw field/path/version spelling. Never infer permissions, current runtime availability, fees, limits, or legal eligibility from examples.
6. Update the coverage matrix and Persian-first knowledge base; retain broken/blocked/not-found pages and exact observed result. Do not claim complete coverage while sitemap or navigation sources remain unreviewed.
7. Run the source and citation validators offline; record actual outcomes. This skill is a repository procedure, not a slash command in the current Arena environment.
